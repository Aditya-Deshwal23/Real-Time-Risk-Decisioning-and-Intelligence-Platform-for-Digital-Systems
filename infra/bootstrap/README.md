# infra/bootstrap/

**Responsibility:** Repeatable local bootstrap resources needed to initialize the development environment.

**Must never contain:** Application business logic, real credentials, or manually maintained cloud state.

**First implementation phase:** Phase 2 — Development environment and containers.

## Bootstrap

`bootstrap.sh` runs `bootstrap.sql` idempotently. It creates or updates:

- `verdict_owner`, `verdict_app`, `verdict_worker` roles
- `keycloak` role
- `verdict` database
- `keycloak` database

The migration owner owns the `verdict` database and `public` schema. The application role receives DML through default privileges, is not a superuser, and has no `BYPASSRLS`. The bootstrap also removes public schema creation rights and grants only usage to runtime roles.

Bootstrap passwords come from ignored `.env` values generated by `infra/compose/dev.py`. Re-running bootstrap preserves object names and updates local role passwords without duplicating databases or roles.

## Kafka topics

`topics.json` is the declarative topic source. `topics.py bootstrap` creates missing topics and reports partition/config drift. CP-02.2 defines only `verdict.smoke.v1`; real event topics remain deferred to their feature phases. Automatic topic creation is disabled.

## Object buckets

`buckets.json` declares the MinIO buckets. `buckets.py` uses the source-built MC helper to create missing buckets idempotently. The local access key and secret are generated into ignored `.env`.
