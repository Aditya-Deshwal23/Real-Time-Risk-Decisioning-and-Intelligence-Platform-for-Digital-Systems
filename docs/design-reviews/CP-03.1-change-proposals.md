# CP-03.1 UI context change proposals

Status: awaiting owner approval

## PD-3 — Theme preference storage key

The implementation uses `verdict-theme-preference` in `console/public/theme-init.js` and `console/src/theme/ThemeProvider.tsx`. `ui-context.md` specifies the choices and fallback behavior but does not name a storage key. Proposed amendment: add `verdict-theme-preference` to section 16 as the owner-readable key.

## PD-4 — Metric-adjusted font fallbacks

The implementation uses `system-ui` and `ui-monospace` fallback stacks with `font-display: swap`. `ui-context.md` requires metric-adjusted fallbacks where feasible but does not provide ascent, descent, line-gap or size-adjust measurements. Proposed amendment: publish measured fallback-face overrides for IBM Plex Sans and IBM Plex Mono after browser font metrics are tested.

## PD-5 — Light status mark exception

Owner decision for CP-03.1: `check_contrast.py` exempts only the light-theme review amber (`#FAB219` on `#FFFFFF`) and degraded orange (`#EC835A` on `#FFFFFF`) mark pairs, matching `UX-19` and section 7.3's explicit by-design note. Proposed amendment: record this checker exception and the no-standalone-mark rule in the contrast implementation section.

## PD-6 — Tailwind breakpoint mapping

Breakpoints remain one source in `console/src/styles/tokens.css`. Tailwind cannot emit media queries from CSS custom-property references in `@theme`, so breakpoint utility mappings are omitted until a verified Tailwind-native mapping is selected. Proposed amendment: state in section 7.1 that breakpoint names are CSS token values and that components use the CSS variables in responsive rules.
